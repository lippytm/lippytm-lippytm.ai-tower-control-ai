# Diversity and Flexibility Rules

Prompt #11 should preserve a diverse and flexible portfolio.

## Purpose

Diversity prevents the ecosystem from depending on one repo, one product, one service, one platform, one tool, or one audience.

Flexibility makes each useful output easier to reuse, adapt, package, and improve.

## Diversity Areas

Track diversity across:

- repositories
- product formats
- service formats
- platform surfaces
- learning paths
- creative systems
- language stacks
- automation channels
- customer audiences
- revenue models

## Flexible Asset Types

A useful output should be reusable as at least one of:

- checklist
- guide
- template
- prompt pack
- repo pattern
- service process
- dashboard section
- learning module
- support script
- product brief
- platform component

## Portfolio Balance Questions

1. Are too many ideas stuck in one lane?
2. Is there a near-term revenue path?
3. Is there a long-term platform path?
4. Is there an education or learning path?
5. Is there a reusable template path?
6. Is there a documentation path?
7. Is the idea small enough to test?
8. Can this be adapted to another repo or audience?

## Flexibility Checklist

- [ ] Can it be reused?
- [ ] Can it be adapted?
- [ ] Can it be documented?
- [ ] Can it be tested small?
- [ ] Can it become a product, service, or internal tool?
- [ ] Can it connect to a repo or dashboard?

## Principle

A strong portfolio has many lanes, but every lane still needs purpose, quality, review, and next action.
