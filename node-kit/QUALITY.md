# Quality Standard

Quality is Job #1 for every Prompt #11 repo node.

## Quality Principles

- Keep changes small and reviewable.
- Make purpose clear.
- Document assumptions.
- Add validation steps.
- Avoid unrelated changes.
- Do not expose secrets.
- Keep business, education, creative, and experimental lanes clearly separated.
- Prefer durable GitHub records over temporary chat instructions.

## Required Review Checklist

Before a PR is ready:

- [ ] Purpose is clear.
- [ ] Scope is limited.
- [ ] Acceptance criteria are included.
- [ ] Validation steps are included.
- [ ] Relevant docs are updated.
- [ ] Risk level is identified.
- [ ] No secrets are committed.
- [ ] No unrelated files are changed.
- [ ] Next action is documented.

## Validation Options

Use whatever applies:

- automated tests
- lint checks
- build checks
- docs review
- manual walkthrough
- screenshot or output evidence
- GitHub Actions workflow result
- reviewer confirmation

## Definition of Done

A task is done when:

1. The requested change is complete.
2. QA or manual validation is recorded.
3. RiskGate is satisfied when required.
4. Documentation is updated when needed.
5. The next action is visible.

## Quality Failure Handling

If quality is unclear, the task should move back to review instead of being merged.
